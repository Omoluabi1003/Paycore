# PayCore interface system

Use UI/UX Pro Max's verified keyboard navigation, responsive table and controlled-form guidance with PayCore's established identity. The generated marketing/gateway and dark-only themes were not a verified fit for an operational payroll workspace; they are not adopted. This is a reviewed product-specific direction, not an unmodified generated theme.

Source: nextlevelbuilder/ui-ux-pro-max-skill, commit b7d5353e0130feb8c5574ef1251f8a1db1873ccb. Local skill: .agents/skills/ui-ux-pro-max/SKILL.md.

- Preserve the existing dimensional PayCore logo, approved splash and ETL GIS Consulting LLC attribution.
- Use navy/teal for structure and primary actions, white surfaces, a quiet gray-green canvas, and restrained warm accents. No new external fonts, UI dependency or decorative animation is required.
- Use the system font stack, normal-text contrast of at least 4.5:1, visible keyboard focus, 44px primary controls, and 16px form text on small screens.
- Present one clear main action per section. Keep local profile access distinct from verified secure mailbox access. Never imply credentials, payments or mailbox connections are live when they are not.
- Use consistent 8/16/24/32px spacing, 12/16/24px radii, and modest border/shadow separation. Keep dense financial tables readable and scroll inside a named, keyboard-focusable region.
- Real data only: do not add sample totals, invented trends, trust badges, certifications or simulated connection states to ordinary product screens.
- Navigation must work on desktop and mobile, identify the current page, restore focus after dialogs, and explain unavailable sections.
- Retain all existing financial calculations, recorded-payment semantics, approval gates, storage keys, server authorizations, request limits and scheduler protections.
- Verify entry, profile editing, schedule setup, payroll entry, invoices, email setup and recorded-document states at 375, 768, 1024 and 1440px. Use synthetic data for browser checks. Check reduced motion, keyboard navigation, error/empty states and automated accessibility; do not claim full WCAG conformance from automated checks alone.
