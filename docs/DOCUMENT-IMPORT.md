# Invoice and receipt review prototype

The first release demonstrates the review flow using **supplied fictional samples only**. Private file selection is disabled. The local workspace profile is not authorization; private business-document ingestion cannot be enabled until server-verified sessions/membership and secure private storage exist. `/api/document-access` fails closed with HTTP 503 and `privateImportEnabled: false`; it accepts no document body or profile credentials.

## Available workflow

Open a workspace profile, choose **Scan documents**, then try a sample PDF, text invoice or receipt CSV. Scan runs actual extraction on the supplied sample, saves a pending sample review, and permits editing its billing fields. The user must check required vendor/reference/date/positive USD total and explicitly confirm before recording. Editing a field resets confirmation. Recorded sample records appear in the existing Activity Register and `/scan/activity`; pending sample reviews appear in Exceptions and `/scan/inbox`. Recorded records are read-only. No customer invoice, payroll transaction, deduction, approval or payment is created.

The sample PDF is generated by `/sample-invoice.pdf` entirely from fixed fictional fixture data. No request, customer or workspace data enters that public document. PDF.js 6.5.438 runs in the browser with a bundled same-origin worker. No external OCR, AI or email service receives the sample contents.

Exact sample-file fingerprints prevent repeated imports. Matching normalized vendor/reference values produce a warning and require a separate-document explanation for distinct sources. Dismissed sample reviews remain in local history and allow replacements. Duplicate matching covers only the incoming sample collection, not historical manually entered payroll receipts.

## Extraction implementation

The reader is implemented for readable PDFs, text and single-record CSVs, with limits of 25 MB, 30 PDF pages and 100,000 extracted characters. CSV maps parsed cells directly into fields, preserving quoted multiline addresses and references containing spaces; it rejects multiple billing rows and duplicate headers. Supported columns include vendor/reference/date/total, optional address/phone/currency/loadReference/kind, and common invoice/receipt aliases. Dates support ISO or US month/day/year. Ambiguous totals and detected foreign currencies require correction; USD only is supported.

Images and PDFs without selectable text have an explicit manual-entry fallback in the reader. Private file selection, OCR, Excel/batch import and mailbox automation are not enabled by this prototype. Descriptive assignment/load labels are not verified contractor links.

## Sample persistence

Sample books have `mode: SAMPLE` and are scoped to the local display-name/company pair under `paycore-document-import-sample-v1:<encoded-profile-scope>`. These profile labels segregate fictional examples; they do not establish identity or tenant access. Different origins, including PR previews, have separate sample collections. No original binaries are archived. Metadata, extracted sample text, edited fields and reviewer evidence survive refresh; the inbox provides a JSON sample-records backup. Backup restoration is not implemented.

Books are validated before writes; unreadable saved copies are preserved. Writes reload current state to reject overwriting already recorded entries. Storage events refresh other tabs, but localStorage does not provide transactional cross-tab uniqueness. Limits are 300 sample records, 8 MB decoded JSON and the browser's actual storage quota; failures are visible. Reverting does not delete sample data.

## Before private use

Connect authenticated sessions and company membership verification on the server for every private read/write, private original-file storage, durable document/record persistence, and server duplicate constraints. Only then replace the fail-closed access route and connect private uploads. Add malware/OCR processing, durable jobs and mailbox OAuth for background ingestion. No browser-only profile or configurable public flag should unlock private document handling.

## Verification and rollback

Unit tests cover extraction, ambiguous/foreign totals, dates, exact cents, review gates, fingerprints, reference-duplicate explanations, immutable recorded state, scoped sample books and corruption, plus quoted/multiline/multi-record CSV cases. Browser checks cover supplied PDF/text/CSV extraction, saved-review recovery, explicit recording, duplicates, sample backup and mobile layouts. Private files remain disabled. Production build, typecheck and dependency audit are required; physical Safari is unverified.

Rollback by reverting this feature's commits. Existing payroll/invoice/approval schemas are unchanged. Retain the sample localStorage key for recovery. No real company records or private files belong in repository fixtures.
